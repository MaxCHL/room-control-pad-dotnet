試試看:上方場景鍵(閱讀/睡眠/離房/勿擾)會一次改變多個裝置——這在系統裡是一則 room/1203/scene/set 情境指令,Gateway 收到後在同一把鎖內序列化套用旗下所有裝置(不被其他指令插隊),而不是 Pad 逐一送;但若中途某個裝置失敗,已套用的裝置不會回滾。

送餐機器人按下「呼叫送餐」會逐步跑過:接單 → 廚房準備 → 指派機器人 → 配送中 → 抵達房門 → 完成。 每一步都是後端服務把狀態發到 room/1203/service/notify,Pad 訂閱後即時更新。

離線也不怕:裝置狀態以 retained 訊息保存,Pad 一連上就拿到房間現況; Gateway 斷線由 Last Will 立即標記,Pad 顯示離線而非顯示過期狀態。

Architecture · Zigbee vs MQTT

分層架構:軟體層 MQTT、裝置層 Zigbee

不是二選一。Pad、Gateway、後端服務之間走 MQTT(軟體);Gateway 到實體燈/窗簾/電視/空調 走 Zigbee / DALI / IR / KNX(韌體)。Gateway 是兩層的翻譯官——這一刀切得清楚,職責邊界也好說明。

說明
本頁為技術展示,使用虛構旅宿連鎖 Nestay 與虛構資料,與任何真實企業無關。 附帶的 C# 模擬以記憶體 message bus 實作 MQTT 語意、裝置層以 IDeviceDriver 抽象(不模擬 Zigbee 無線電); 正式環境走真實 MQTT broker、真實 Zigbee/KNX/DALI 閘道,狀態存 DB、通知走推播。

附帶可編譯的 C# 模擬(.NET 10):RoomControl.Core 定義裝置/情境模型、 MQTT 介面、IDeviceDriver 裝置層抽象、冪等指令;RoomControl.Sim 以記憶體 bus 模擬 Pad、房間 Gateway 與送餐機器人 / 設施人數 / 餐廳排隊後端服務的完整互動。
